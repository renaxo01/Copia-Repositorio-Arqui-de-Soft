# 3.3. Consolidación de Escenarios

| ID Escenario | Atributo de Calidad | Estímulo | Respuesta | ID Escenario Preliminar | Sustento | Módulo |
|---|---|---|---|---|---|---|
| CONS-01 | Rendimiento / Seguridad | 5,000 usuarios concurrentes con carrito activo y 20 checkouts por segundo; Un comprador modifica el precio en la solicitud de checkout | Procesa las operaciones sin degradación; Recalcula los precios con el Catálogo y rechaza la solicitud si hay diferencia | ESCP-01, ESCP-02 | `ESC-PED-03`, `ESC-PED-05` del apartado 2.2 | Carrito, Pedidos y Notificaciones |
| CONS-02 | Interoperabilidad | Pagos publica el evento `PagoConfirmado`, incluso duplicado; Se crea un subpedido | Confirma el pedido una sola vez; Publica `SubpedidoCreado` con un contrato versionado para Logística y el vendedor | ESCP-03, ESCP-04 | `ESC-PED-07`, `ESC-PED-08` del apartado 2.2 | Carrito, Pedidos y Notificaciones |
| CONS-03 | Disponibilidad / Seguridad | El servicio externo de validación de RUC/DNI no responde; Un vendedor crea cuentas falsas para publicar reseñas positivas de sus productos | El registro se acepta, la verificación queda pendiente y se reintenta automáticamente; Solo acepta reseñas vinculadas a un subpedido entregado y marca patrones sospechosos | ESCP-05, ESCP-06 | `ESC-VEN-01`, `ESC-VEN-06` del apartado 2.2 | Vendedores, Reputación y Disputas |
| CONS-04 | Interoperabilidad | Operaciones resuelve una disputa a favor del comprador; Logística publica el evento `EntregaConfirmada` | Publica el evento `DisputaResuelta` con el monto a reembolsar para que Pagos lo procese; Habilita al comprador para reseñar el subpedido entregado | ESCP-07, ESCP-08 | `ESC-VEN-07`, `ESC-VEN-08` del apartado 2.2 | Vendedores, Reputación y Disputas |
| CONS-05 | Disponibilidad / Rendimiento | Falla el motor de búsqueda; 400 búsquedas por segundo | Opera en modo degradado: navegación por categorías y fichas de producto siguen disponibles; Devuelve resultados relevantes con filtros aplicados | ESCP-09, ESCP-10 | `ESC-CAT-01`, `ESC-CAT-03` del apartado 2.2 | Catálogo y Búsqueda |
| CONS-06 | Interoperabilidad | Pedidos consulta precio y stock vigente durante el checkout; Vendedores publica el evento `VendedorSuspendido` | Responde precio y stock vigentes mediante una API versionada; Oculta todos los productos del vendedor suspendido | ESCP-11, ESCP-12 | `ESC-CAT-07`, `ESC-CAT-08` del apartado 2.2 | Catálogo y Búsqueda |
| CONS-07 | Disponibilidad / Seguridad | La API de un courier no responde; Se envía una notificación falsa de entrega | Reasigna el envío a otro courier con cobertura o encola la generación para reintentarla; Rechaza la notificación sin autenticación válida del courier y la registra | ESCP-13, ESCP-14 | `ESC-LOG-01`, `ESC-LOG-05` del apartado 2.2 | Logística |
| CONS-08 | Interoperabilidad | Un courier informa estados por API y otro mediante un archivo diario; Un courier confirma una entrega | Convierte ambos formatos a un modelo común de estados; Publica `EntregaConfirmada` con el ID del subpedido y la evidencia de entrega para Pagos y Vendedores | ESCP-15, ESCP-16 | `ESC-LOG-07`, `ESC-LOG-08` del apartado 2.2 | Logística |
| CONS-09 | Disponibilidad / Seguridad | La pasarela no responde al cobro (timeout mayor a 10 s); Se intenta obtener datos de tarjeta desde la base de datos, logs o respaldos | No reintenta el cargo a ciegas: registra el pago como pendiente, consulta su estado e informa al comprador; Los datos de tarjeta nunca ingresan al backend; solo se almacenan tokens y los últimos 4 dígitos | ESCP-17, ESCP-18 | `ESC-PAG-01`, `ESC-PAG-05` del apartado 2.2 | Pagos y Liquidaciones |
| CONS-10 | Seguridad / Interoperabilidad | Se envía un webhook falso indicando un pago aprobado; Logística publica el evento `EntregaConfirmada`, incluso duplicado | Rechaza la notificación por firma inválida, la registra y genera una alerta; Inicia el periodo de reclamo del subpedido; un duplicado no genera efectos adicionales | ESCP-19, ESCP-20 | `ESC-PAG-06`, `ESC-PAG-10` del apartado 2.2 | Pagos y Liquidaciones |

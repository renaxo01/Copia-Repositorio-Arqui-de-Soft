# 2.1.4. Módulo 4 / Integrante 4 (SANTIN)

**Módulo:** Logística · **Responsable:** SANTIN

El módulo conecta la plataforma con varios couriers externos, cada uno con su propia forma de comunicación, para cotizar, despachar y seguir los envíos. Su salida más importante es el evento `EntregaConfirmada`, que habilita la liberación del pago al vendedor y la reseña del comprador.

## Requisitos funcionales

| ID | Requisito | Actor | Descripción | Prioridad | Escenarios relacionados |
|---|---|---|---|---|---|
| RF-LOG-01 | Cotizar envío | Sistema | Calcular el costo y plazo de envío de un subpedido según distrito de origen y destino, peso y dimensiones, y devolverlo a Pedidos. | Alta | ESC-LOG-03 |
| RF-LOG-02 | Configurar tarifas y cobertura | Coordinador logístico | Mantener la tabla de tarifas por distrito y la cobertura de cada courier sin desplegar código. | Media | ESC-LOG-10 |
| RF-LOG-03 | Asignar courier | Sistema | Al recibir `SubpedidoCreado`, asignar el courier según cobertura, costo y disponibilidad. | Alta | ESC-PED-08 |
| RF-LOG-04 | Generar guía de envío | Sistema | Solicitar al courier la guía de envío y poner la etiqueta a disposición del vendedor para el despacho. | Alta | ESC-LOG-01 |
| RF-LOG-05 | Reasignar envío | Sistema | Si la API de un courier no responde, reasignar el envío a otro courier con cobertura o encolar la generación para reintentarla. | Alta | ESC-LOG-01 |
| RF-LOG-06 | Recibir estados por API | Sistema | Recibir actualizaciones de estado de los couriers por API o webhook, aceptando solo notificaciones autenticadas. | Alta | ESC-LOG-04, ESC-LOG-05 |
| RF-LOG-07 | Importar archivo de estados | Sistema | Procesar el archivo diario de estados de los couriers sin API y convertirlo al modelo común de estados. | Media | ESC-LOG-07 |
| RF-LOG-08 | Seguir envío | Comprador / Vendedor | Consultar el estado actual y el historial del envío; si el servicio de seguimiento falla, mostrar el último estado conocido. | Alta | ESC-LOG-02 |
| RF-LOG-09 | Confirmar entrega | Sistema | Registrar la entrega con su evidencia (foto, firma o código) y publicar `EntregaConfirmada` para Pagos, Vendedores y Pedidos. | Alta | ESC-LOG-08 |
| RF-LOG-10 | Gestionar entrega fallida y devolución | Coordinador logístico | Registrar intentos de entrega fallidos, reprogramar la entrega o gestionar la devolución al vendedor. | Media | — |
| RF-LOG-11 | Restringir datos de envío | Sistema | Mostrar al courier y al vendedor solo los datos mínimos del destinatario del subpedido asignado, y por tiempo limitado. | Alta | ESC-LOG-06 |
| RF-LOG-12 | Administrar couriers | Coordinador logístico | Registrar, activar o desactivar couriers y configurar su forma de integración (API o archivo). | Baja | ESC-LOG-09 |

**Prioridad:** Alta = imprescindible para el MVP · Media = necesaria antes del lanzamiento · Baja = mejora posterior.
La columna *Escenarios relacionados* enlaza cada requisito con los escenarios de calidad del apartado 2.2.
